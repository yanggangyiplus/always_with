# scope-check

새 기능 요청을 받으면 구현 전에 아래 순서로 판단한다.

1. `01_PM/기획문서.md`의 1.5(1차 범위)와 2.2(요구사항 ID)를 읽는다.
2. 요청이 어느 요구사항(FR-xx)에 해당하는지 찾는다. 없으면 "범위 밖 후보"로 표시한다.
3. `01_PM/02_성공지표_우선순위.md`의 성공 지표(소통, 위험 알림) 중 어느 것을 움직이는지 적는다. 움직이는 지표가 없으면 뺀다.
4. Must, Should, Could 중 하나로 분류하고, 11/2 코드 동결까지 남은 시간으로 가능한지 말한다.
5. 결과를 4줄로 답한다: 해당 요구사항, 영향 지표, 분류, 권고(넣기 / 미루기 / 빼기).
6. 미루거나 뺀 기능은 이유와 함께 `01_PM/02_성공지표_우선순위.md`의 "뺀 기능" 표에 추가한다.

규칙:

- 핵심 흐름 두 가지를 흔드는 요청이 먼저다: 소통(피드, 채팅, 부탁, 일정, 위치)과 위험 알림(카메라 → 판정 → 알림 → 타임라인).
- 지표는 소통 지표와 위험 알림 지표 중 어느 쪽을 움직이는지 구분해 적는다.
- 예외 상황(이탈, 데이터 없음)을 정의하지 않은 기능은 Must로 올리지 않는다.
