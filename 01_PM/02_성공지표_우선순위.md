## 소통 지표

소통 지표는 연결된 두 계정(보호자 A, 부모님 B)에서 서로의 글과 메시지가 바로 보이는지를 봐요.
가족이 서로 돌보려면 한쪽이 올린 것이 상대 화면에 곧바로 보여야 하기 때문이에요.
목표값은 제가 제안한 잠정값이라 확정이 필요해요. 현재 값은 아직 재지 못했어요.

| 지표 | 정의 | 잠정 목표 | 현재 값 |
| --- | --- | --- | --- |
| 피드 전달 | A가 글을 올린 뒤 B 화면에 새로고침 없이 나타나기까지 걸린 시간 | 5초 이내, 10회 중 10회 | 측정 안 함 |
| 채팅 전달 | A가 보낸 메시지가 B 화면에 나타나기까지 걸린 시간 (A에서 B) | 5초 이내, 10회 중 10회 | 측정 안 함 |
| 채팅 주고받기 | B가 답장하면 A 화면에 나타나기까지 걸린 시간 (B에서 A) | 5초 이내, 10회 중 10회 | 측정 안 함 |

5초는 화면이 3초마다 새로 불러오는 방식(채팅과 피드 모두)이라서 최악의 경우 3초에 처리 시간을 더한 값이에요.

### 측정 방법

1. 서버를 켜고 보호자 계정 A와 연결된 부모님 계정 B를 준비해요.
2. 브라우저 창 두 개를 나란히 열어요. 일반 창에 A, 시크릿 창에 B로 로그인해요. 로그인 정보가 브라우저에 저장되므로 같은 창에서는 두 계정을 함께 쓸 수 없어요.
3. A에서 글을 올리는 순간부터 B 화면에 나타날 때까지 초시계로 재요. 10번 반복해요.
4. 채팅은 A에서 B, B에서 A 방향으로 각각 10번씩 재요.
5. 새로고침을 누르지 않았는지 확인하고, 결과를 위 표에 옮겨요.
6. 나타나지 않은 경우는 시간 대신 "실패"로 적고 원인을 한 줄 적어요.

### 알아 둘 점

- 채팅은 처음부터 3초마다 새로 불러왔고, 피드는 새로고침해야만 새 글이 보였어요. 10/29에 피드도 3초마다 새로 불러오게 바꿨어요.
- 이 방식은 WebSocket 같은 진짜 실시간(서버가 즉시 밀어 주는 방식)이 아니에요. 모바일 앱으로 옮길 때 푸시로 바꿔요.
- 피드 사진은 글보다 늦게 보일 수 있어요. 이번 측정은 글이 나타나는 시점만 재요.

## 위험 알림 지표

1차 위험 알림은 낙상 감지예요. 외출 기록 같은 다른 위험 알림은 지표를 아직 정하지 않았어요.

| 지표 | 목표 (사전 설정) | 현재 값 | 근거 |
| --- | --- | --- | --- |
| 낙상 재현율 | 90% 이상 | 92% (합성 12건 중 11건) | [평가리포트](../03_개발/docs/평가리포트.md). 합성 시퀀스라 실제 값이 아니에요 |
| 일상 동작 오탐률 | 베이스라인을 본 뒤 확정 | 57%에서 21%로 감소 (합성 14건) | 같은 리포트. 목표값은 아직 못 정했어요 |
| 낙상 판정부터 알림까지 | 10초 이내 | 측정 안 함 | 판정 시각과 알림 시각을 로그로 비교하는 작업이 남았어요 |

## 우선순위

Must는 가족이 서로 돌보는 흐름과 위험 알림 흐름이 모두 돌아가는 데 필요한 것이에요.

| 등급 | 의미 | 포함한 것 |
| --- | --- | --- |
| Must (소통) | 가족이 서로 쓸 수 없으면 서비스가 성립하지 않아요 | 로그인, 보호자와 부모님·아이 연결(동의), 가족 피드, 실시간 채팅, 부탁해, 일정, 위치 공유(본인이 켤 때만) |
| Must (위험 알림) | 위험을 알리는 핵심 흐름이에요 | 카메라 등록, 웹캠 분석, 낙상 판정, 이벤트와 인앱 알림, 타임라인, 오탐 신고, 성능 리포트(평가 결과 파일 연결 전) |
| Should | 신뢰를 높여요 | 피드 공개 범위, 채팅의 피드 글 답장, 알림 병합, 오프라인 알림, 스켈레톤 라이브 뷰, 일시정지 |
| Could | 있으면 좋아요 | 재알림, 클립 자동 삭제 |

위치 공유는 "감시가 아니라 안부를 나누는 느낌"이어야 해서 본인이 켰을 때만 보내고, 끄면 저장된 위치를 지워요.

## 뺀 기능과 이유

| 기능 | 뺀 이유 | 다시 볼 시점 |
| --- | --- | --- |
| 외출 기록 | 위험 알림은 낙상으로 시작했고, 외출은 위치 기록과 동의 설계가 먼저 필요해요 | 2차 |
| 피드 댓글 | 채팅 답장이 같은 역할을 해요 | 2차 |
| 푸시 알림(Web Push) | 5일 안에 앱 안 알림(인앱)을 먼저 끝내야 해요 | 2차(모바일 앱 전환 때 함께) |
| 낙상 학습 모델 | 데이터셋 확보와 라이선스 확인이 먼저고, 규칙 기준선을 먼저 잰 뒤 비교해요 | 10/30 이후 |
| 백그라운드 위치 추적 | 웹은 앱을 닫으면 위치를 못 보내요 | 모바일 앱 전환 때 |
| 아이 대상 낙상 모델 | 합법적으로 얻은 아동 데이터가 없어요 | 데이터 확보 시 |
| 다중 카메라, 모바일 앱, 복약 체크, SOS | 1차 범위 밖이에요 | 3~4차 |
| 사진 외부 저장소 | 사진은 DB에 저장해 단순하게 갔어요. 배포 때 용량을 다시 봐야 해요 | 배포 때 |
