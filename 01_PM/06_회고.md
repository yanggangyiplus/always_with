# 회고

소통 기능은 넓게 만들었지만 사용 데이터로 확인하지 못했고, 낙상 감지는 실제 영상으로 검증하지 못했어요.

## 맞바꾼 것

| 선택 | 얻은 것 | 잃은 것 |
| --- | --- | --- |
| 소통 기능(피드, 채팅, 부탁, 일정, 위치)을 먼저 넓게 구현 | 가족이 평소에 쓸 이유가 생겨요 | 낙상 감지 검증에 쓸 시간이 줄었어요 |
| 위험 알림을 낙상 하나로 시작 | 핵심 흐름을 끝까지 만들어요 | 외출 기록 같은 다른 위험은 아직 없어요 |
| 학습 모델 대신 규칙 기반 판정 | 빠르게 구현하고 이유를 설명할 수 있어요 | 천천히 눕는 동작, 숙이는 동작을 못 구분해요 |
| 오탐을 줄이려고 1초 유지와 직전 서 있음 조건 추가 | 오탐률 57%에서 21% | 경보가 1.1초 늦어요 |
| 사진을 DB에 저장 | 서버 하나로 단순해요 | 배포 때 용량 문제가 생길 수 있어요 |
| 채팅을 3초마다 새로 불러오기 | WebSocket 없이 구현해요 | 지연과 불필요한 요청이 있어요 |
| 메인 백엔드에서 직접 추론 | 프로세스 하나로 실행해요 | 서버를 여러 대 띄우면 카메라 상태가 갈라져요 |
| 위치는 본인이 켰을 때만 60초마다 전송 | 감시가 아닌 안부 느낌 | 앱을 닫으면 위치가 갱신되지 않아요 |
| 인앱 알림만 구현 | 5일 안에 흐름을 완성 | 앱을 닫으면 알림을 받지 못해요 |

## 잘한 점

- 소통은 "두 계정에서 서로 보이는 시간", 위험 알림은 "재현율과 오탐률"로 지표를 나누어 정했어요.
- 지표를 정하다가 피드가 새로고침해야만 갱신되는 것을 발견해 3초마다 새로 불러오게 고쳤어요.
- 합성 시퀀스에 "까다로운 경우"를 넣어 규칙이 틀리는 곳을 드러냈어요.
- 막는 동작을 테스트 20개로 남겼어요.

## 한계

- 소통 지표는 정의만 했고 아직 재지 못했어요. 목표값(5초)은 잠정이에요.
- 피드와 채팅은 진짜 실시간이 아니라 3초마다 새로 불러오는 방식이에요.
- 부탁, 일정, 위치의 소통 지표는 정하지 않았어요.
- 낙상 기준값(60도, 1초, 5초)은 가정값이에요.
- 낙상 평가는 합성 시퀀스이고 실제 영상은 0건이에요.
- 알림 10초 이내 목표는 재지 않았어요.
- 사용자 테스트를 하지 않았어요.
- 아이 대상 감지는 검증하지 않았어요.

## 다음 단계

1. 두 계정으로 피드와 채팅 전달 시간을 10회씩 재요.
2. WebSocket이나 푸시로 바꿔 전달 시간을 줄여요.
3. 공개 낙상 데이터셋(라이선스 확인 후)으로 실제 영상 20~30건을 평가해요.
4. `yolo26n-pose`와 `yolo26m-pose`의 속도와 정확도를 비교해요.
5. 판정부터 알림까지 지연을 로그로 재요.
6. 외출 기록을 두 번째 위험 알림으로 설계해요(동의와 위치 기록 정책 먼저).
7. Web Push와 모바일 앱 전환, 배포를 해요.
