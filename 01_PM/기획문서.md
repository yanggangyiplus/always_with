# Always with — 가족 케어 앱 기획 문서 (부모님·아이)

Oct 28, 2026 · @양갱이

## 1. 기획서

Always with는 언제 어디서나 가족이 서로를 돌보는 가족 돌봄 웹앱(추후 모바일 앱 전환 예정)입니다. 평소에는 피드 공유, 실시간 채팅, 부탁, 일정, 위치 공유로 소통하고, 위급할 때는 AI가 낙상을 감지해 알려 주는 위험 알림을 보냅니다. 1차(10/28\~11/3)에서는 가족 소통 기능과 낙상 감지 코어, 보호자 알림을 완성하고, 돌봄 대상을 부모님과 아이로 나누는 구조와 아이 전용 기능 2종(위험 구역 접근, 취침 구역 이탈 알림)까지 갖춥니다. 외출 기록 등 다른 위험 알림과 모바일 앱 전환은 이후 단계에서 다루고, 2차(MVP 3, 4)는 부모님과 아이 모두에 구현합니다.

### 1.1 배경과 문제

- 떨어져 사는 가족은 안부를 나누고 서로 부탁할 창구가 메신저, 전화, 사진 앱으로 흩어져 있습니다.
- 혼자 사는 부모님이 넘어졌을 때, 자녀가 곧바로 알 방법이 마땅치 않습니다.
- 웨어러블은 착용을 잊거나 거부하기 쉽고, 일반 홈캠은 보호자가 계속 영상을 봐야 하며 부모님에게는 감시받는 느낌을 줍니다.
- 따라서 평소에는 조용히 있다가 이상 상황에서만 알리고, 영상 노출을 최소화하는 방식이 필요합니다.

같은 보호자가 부모님과 아이를 함께 챙기는 경우도 많습니다. 돌봄 대상별로 앱을 따로 쓰면 알림과 확인 방식이 흩어지므로, 한 앱에서 돌봄 대상 유형만 나누는 방식이 효율적입니다.

### 1.2 목표

| 구분 | 목표 | 1차 지표 (잠정) |
| --- | --- | --- |
| 프로덕트 | 낙상 후 보호자가 빠르게 인지 | 낙상 판정 후 알림 10초 이내 |
| 소통 | 연결된 두 계정에서 서로의 글과 메시지가 바로 보임 | 피드 전달, 채팅 전달(A→B, B→A) 각각 5초 이내, 10회 중 10회 |

### 1.3 타깃 사용자

사용자는 20~50대 보호자, 아이, 부모님 세 부류이고 한 가족으로 연결됩니다.

| 구분 | 20~50대 보호자 | 아이 | 부모님 |
| --- | --- | --- | --- |
| 예시 | 타지에 사는 20~50대 자녀, 아이를 키우는 부모 | 보호자가 돌보는 아이 | 혼자 사는 60대 이상 |
| 불안 | 쓰러지거나 위험한 곳에 가도 모를까 봐 걱정 | 놀이 중 넘어지거나 위험한 곳에 가고 잠자리에서 일어나 돌아다닐 수 있음 | 자식에게 부담이 되기 싫고 감시받는 느낌이 싫음 |
| 필요 | 안부 나누기, 이상 상황의 빠른 인지와 확인 | 보호자가 곁에 없어도 위험할 때 알려 주는 것 | 최소한의 조작, 사생활 보호, 동의 존중 |
| 앱에서의 역할 | 알림 수신, 카메라 등록, 초대 코드 발급, 클립 확인, 이력 조회 | 보호자 동의 뒤 초대 코드로 계정을 연결해 피드와 채팅에 참여 | 카메라 기기 제공, 연결 동의, 피드와 채팅, 부탁 |

아이의 불안과 필요는 기획 단계의 가정이며 아직 사용자에게 확인하지 않았습니다.

### 1.4 핵심 가치와 차별점

1. 이상할 때만 알립니다. 평소에는 보호자가 영상을 계속 볼 필요가 없습니다.
2. 프라이버시가 기본값입니다. 평소에는 관절 선(스켈레톤) 화면만 보이고, 원본 영상은 이상 감지 시의 짧은 클립만 저장합니다.
3. 오탐 신고가 모델 개선 데이터가 됩니다. 보호자의 신고를 재학습 후보로 쌓는 구조입니다.
4. 성능을 숫자로 보여줍니다. 데이터셋 간 교차 평가와 혼동 행렬을 앱 안의 리포트 페이지로 제공합니다.

5. 가족이 서로 돌봅니다. 보호자만 보는 감시 도구가 아니라 부모님과 아이도 피드, 채팅, 부탁으로 먼저 말을 거는 쌍방향 구조입니다.

이 다섯 가지에 더해, 부모님과 아이를 한 앱에서 구분해 돌볼 수 있다는 점이 양쪽을 동시에 챙기는 보호자의 편의가 됩니다.

### 1.5 1차 범위

| 구분 | 내용 |
| --- | --- |
| 포함 | 가족 소통(피드, 채팅, 부탁해, 일정, 위치 공유), 낙상 감지 코어(MVP 1), 보호자 알림과 이벤트 타임라인(MVP 2), 로그인(이메일, 소셜), 보호자-부모님 연결, 카메라 등록, 모델 평가 리포트, 돌봄 대상 프로필(부모님/아이)과 아이 프로필 등록(베타), 아이 전용 기능 2종(위험 구역 접근 알림, 취침 구역 이탈 알림) |

### 1.6 로드맵: 가족 소통 기반과 MVP 8개

| 차수 | MVP | 핵심 내용 | AI/ML 포인트 |
| --- | --- | --- | --- |
| 1차 | MVP 1. 낙상 감지 코어 | 영상 입력, 포즈 추출, 낙상 판정 | 포즈 추정, 규칙 vs 학습 모델 비교 |
| 1차 | MVP 2. 보호자 알림과 이벤트 타임라인 | 알림, 클립 저장, 오탐 신고 | 오탐/미탐 분석, 피드백 수집 |
| 1차 (추가) | 아이 전용 기능 2종 | 위험 구역 접근 알림, 취침 구역 이탈 알림 (새 모델 학습 없이 구역 기반 규칙) | 구역 규칙 설계, 연출 영상으로 정밀도와 재현율 평가 |
| 1차 (추가) | 가족 소통 | 피드, 채팅, 부탁해, 일정, 위치 공유(본인이 켤 때만). 3초마다 새로 불러오는 방식 | 전달 시간 측정(5초 이내) |
| 2차 | MVP 3. 위치 확인과 안심구역 | 부모님과 아이의 위치 지도, 구역 이탈 알림 | - |
| 2차 | MVP 4. 활동량과 장시간 무동작 감지 | 부모님과 아이의 하루 활동 요약, 이상 무동작 알림 (아이는 활동과 수면 패턴 요약) | 시계열 이상 탐지 |
| 2차 | 외출 기록 | 외출과 귀가 기록. 동의와 위치 기록 정책을 먼저 설계 | - |
| 3차 | MVP 5. SOS 버튼과 일일 안부 체크인 | 긴급 호출, 매일 안부 확인 | - |
| 3차 | MVP 6. 건강 위험 점수 리포트 | 활동과 보행 패턴 기반 주간 리포트 | 보행 분석, 위험 점수 모델 |
| 4차 | MVP 7. 모바일 앱 전환과 엣지 추론 | 기기 내 추론, 백그라운드 위치 | 모델 경량화(ONNX/TFLite) |
| 4차 | MVP 8. 이상 소리 감지와 LLM 요약 | 비명·충격음 감지, 보호자용 일일 요약 | 오디오 분류, LLM 활용 |

웹(PWA)에서 시작해 4차에 모바일 앱으로 옮기고, 서버 API와 AI 모델은 그대로 재사용합니다. 웹은 앱을 닫으면 백그라운드 위치 추적이 안 되므로, 1차와 2차의 위치 기능은 앱이 열려 있을 때 전송한 마지막 위치 기준입니다.

후속 MVP는 돌봄 대상 유형별로 다음처럼 확장하며, 2차(MVP 3, 4)까지는 부모님과 아이 모두에 구현합니다.

| MVP | 부모님 | 아이 |
| --- | --- | --- |
| MVP 3. 위치 확인과 안심구역 | 안심구역 이탈 알림 | 등하교 도착과 안심구역 이탈 알림 |
| MVP 4. 활동량과 장시간 무동작 | 장시간 무동작 알림 | 활동과 수면 패턴 요약 |
| MVP 5. SOS와 안부 체크인 | SOS 버튼, 일일 안부 | 아이가 누르는 도움 버튼, 귀가 확인 |
| MVP 6. 건강 위험 점수 | 보행과 활동 기반 점수 | 위험 동작 빈도 리포트 (탐색 과제) |
| MVP 7. 모바일 앱과 엣지 추론 | 기기 안에서 추론 | 기기 안에서 추론 (아이 영상은 기기 밖으로 보내지 않는 방식을 기본값으로 검토) |
| MVP 8. 이상 소리 감지와 LLM 요약 | 충격음, 도움 요청 소리 | 울음 소리, 일일 요약 |

아이 대상 낙상 감지 전용 모델은 합법적으로 수집한 데이터가 있을 때만 후속 과제로 다룹니다.

### 1.7 기술 구성

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | React 19 + Vite + Tailwind v4 (PWA는 미적용) | 링크로 시연 가능. 홈 화면 설치는 후속 |
| 백엔드 | Python FastAPI(HTTP). 프레임은 브라우저가 반복해서 POST | AI 모델과 같은 언어. WebSocket은 쓰지 않음 |
| DB | SQLite로 시작, PostgreSQL로 전환 가능한 구조(SQLAlchemy) | 1차 속도 우선, 이후 확장 |
| AI | YOLO-Pose(yolo26n-pose)와 규칙 기반 판정 (PyTorch 학습 모델은 후속) | 사전학습 포즈 모델로 학습 데이터 부담을 줄임 |
| 알림 | 인앱 알림(구현), Web Push(구독 정보 저장까지, 발송은 후속) | 별도 비용 없이 구현 (iOS는 홈 화면 설치 후에만 푸시 지원) |
| 가족 소통 | 일반 REST API, 화면이 3초마다 새로 불러오기, 사진은 DB에 저장 | WebSocket 없이 구현. 모바일 앱 전환 때 푸시로 교체 |
| 저장소 | 사진은 DB(JPEG), 클립 저장은 미구현 | 1차 단순화 |

처리 흐름은 다음 순서입니다.

1. 브라우저가 웹캠 프레임을 좌우반전해 JPEG로 서버에 반복해서 보냅니다 (`POST /api/cameras/{id}/analyze`).
2. 서버가 YOLO 포즈 모델(yolo26n-pose)로 관절 좌표를 추출하고, 사람이 여럿이면 가장 큰 사람을 고릅니다.
3. 어깨와 엉덩이 중심으로 몸통 기울기를 계산합니다.
4. 규칙 판정기가 몸통 기울기(60도 이상), 유지 시간(1초), 직전 5초 안의 서 있음을 확인합니다. 학습 모델은 후속입니다.
5. 낙상이면 이벤트와 인앱 알림을 만듭니다(60초 쿨다운). 전후 클립 저장은 아직 구현하지 않았습니다.
6. 보호자는 타임라인과 알림 목록에서 확인합니다. Web Push 발송은 후속입니다.

### 1.11 책임과 한계 (README에 포함)

- 이 서비스는 의료기기가 아닌 가족 돌봄 도구이며, 낙상 알림은 보조 수단으로 모든 낙상을 감지한다고 보장하지 않습니다.
- 가림, 어두운 조명, 다인 환경에서는 성능이 떨어질 수 있다는 한계를 문서화합니다.
- 촬영 대상자의 동의가 필요하며, 영상은 이상 감지 클립만 보관합니다.

## 2. 요구사항 정의서

1차 범위의 기능 요구사항은 32개이며, 이 중 Must 25개를 11/2 코드 동결 전에 반드시 완료합니다.

### 2.1 우선순위 기준

| 등급 | 의미 | 일정 원칙 |
| --- | --- | --- |
| Must | 없으면 1차 데모가 성립하지 않음 | 반드시 완료 |

| Could | 있으면 좋은 기능 | 2차로 미뤄도 무방 |

### 2.4 제약과 가정

- 1차는 단일 인물 기준이며, 여러 사람이 동시에 보이면 가장 크게 보이는 사람을 기준으로 합니다.
- 웹 환경이라 백그라운드 위치 추적과 앱을 닫은 상태의 상시 감시는 지원하지 않습니다.
- 학습과 평가에는 공개 연구용 데이터셋만 사용하며, 각 데이터셋의 라이선스는 사용 전에 확인합니다.
- 성능 수치는 공개 데이터셋 기준 결과이며 실제 가정 환경의 성능을 보장하지 않습니다.

* 아이 대상 낙상 감지는 성인과 고령자 데이터로 학습한 모델을 그대로 쓰므로 정확도를 보장하지 않으며, 베타로 표시합니다.

- 구역 기능(위험 구역, 취침 구역)은 사람 검출 결과에 의존하므로 이불이나 가구에 가려지면 감지하지 못할 수 있으며, 새 모델 학습이 없는 규칙 기반입니다. 정확도는 성인 연출 영상으로 검증합니다.

| F-14 | 구역 설정 (FR-25) | 카메라, 구역 이름, 용도(위험 또는 취침), 화면 위 사각형(0\~1로 정규화한 좌표), 취침 시간대, 기준 시간 | 좌표와 최소 크기 검증, 카메라당 최대 3개 제한, 구역 저장, 라이브 뷰에 겹쳐 표시 | 구역 목록 | 4개째 구역 400, 좌표 범위 밖 422, 아이 프로필이 아닌 카메라에 위험·취침 용도 지정 400, 카메라가 오프라인이면 설정 불가 | 일부 (API만, 화면 없음) |

| F-16 | 가족 피드 (FR-28) | 글, 사진(최대 5장, 장당 2MB), 공개 범위, 좋아요 | 사진은 브라우저에서 1280px로 줄여 올리고 DB에 JPEG로 저장, 공개 범위에 따라 조회 제한, 화면은 3초마다 새로 불러옴 | 피드 목록 | 사진 개수나 용량 초과 400, 남의 글 수정과 삭제 403 | 구현 |

| F-18 | 부탁해 (FR-30) | 제목, 메모, 링크, 상태 | 상태 요청, 주문, 완료로 전이 | 부탁 목록 | 권한 없는 계정 403 | 구현 |
| F-19 | 일정 (FR-31) | 제목, 시작 시각, 메모 | 입력한 현지 시각 그대로 저장 | 캘린더, 다가오는 일정 | 필수값 누락 422 | 구현 |

이벤트 상태는 미확인(new), 확인 완료(acknowledged), 오탐(false\_alarm) 세 가지이고, 미확인에서만 나머지 둘로 바뀝니다.

### 3.2 낙상 판정 모델 명세

현재 구현은 규칙 기반 베이스라인입니다. 몸통 기울기가 60도 이상인 상태가 1초 이상 유지되고, 직전 5초 안에 30도 미만(서 있음)이 있었으면 낙상으로 판정합니다. 아래 표의 2초 윈도우, 특징, 학습 모델, 교차 평가는 후속 계획이며, 현재 평가는 합성 시퀀스 26건입니다(`03_개발/docs/평가리포트.md`).

| 항목 | 정의 |
| --- | --- |
| 입력 | 2초 윈도우(약 30프레임), 0.5초 간격으로 이동 |
| 특징 | 몸통 기울기(어깨 중점과 엉덩이 중점의 수직 대비 각도), 머리 높이 변화 속도, 사람 박스의 가로세로비, 엉덩이 높이, 관절 평균 이동 속도(무움직임 판단용) |
| 베이스라인 (규칙) | 몸통 기울기와 머리 하강 속도가 임계값을 넘으면 후보, 이후 5초간 평균 이동 속도가 낮으면 확정. 임계값(초기 기울기 60도 등)은 검증 데이터로 튜닝 |
| 학습 모델 | 1D-CNN과 GRU 두 가지를 같은 입력으로 학습해 규칙 베이스라인과 비교 |
| 클래스 | 낙상, 일상 동작(걷기, 앉기, 눕기, 줍기 등), 기타 |
| 라벨링 | 데이터셋의 구간 라벨을 윈도우로 변환 (낙상 구간과 절반 이상 겹치면 낙상) |
| 불균형 처리 | 클래스 가중치, 윈도우 샘플링 비율 조정 |
| 데이터 분할 | 사람(subject) 단위로 학습, 검증, 테스트를 나눠 같은 사람이 섞이지 않게 함 |
| 교차 평가 | 한 데이터셋으로 학습하고 다른 데이터셋으로 테스트 |
| 지표 | 재현율, 정밀도, F1, 일상 동작 오탐률, 낙상 1건당 알림 수(이벤트 단위), 혼동 행렬 |
| 오류 분석 | 오탐과 미탐 사례를 모아 원인(가림, 자세, 카메라 각도 등)별로 정리 |
| 산출물 | results/metrics.json (성능 리포트 페이지가 읽는 파일), 학습 재현용 설정과 시드 |
| 아이 대상 적용 | 성인과 고령자 데이터로 학습한 모델을 그대로 적용하고 아이 프로필에는 베타로 표시. 아동 데이터는 합법적 확보와 동의 문제가 해결된 뒤 별도로 평가 |
| 구역 기능 | 학습 모델 없이 규칙 기반. 사람 기준점과 구역의 포함 관계로 판정하며, 성인 연출 영상으로 정밀도와 재현율을 측정하고 한계(가림, 카메라 각도)를 기록 |

학습 모델이 베이스라인보다 낮더라도 그 결과와 원인 분석을 그대로 보여줍니다. 면접에서는 높은 수치보다 비교 설계와 해석이 더 중요한 근거가 됩니다.

## 4. 화면 설계서

1차는 소통 화면 5개를 포함한 18개 화면으로 구성되며, 보호자와 부모님·아이 모두 상단 고정 탭으로 가족 소통 화면(피드, 채팅, 위치, 부탁해, 일정)을 씁니다. 보호자는 여기에 타임라인과 카메라 관리를 더 씁니다.

### 4.1 화면 목록

### 4.2 사용자 흐름

**흐름 A. 보호자 온보딩**

1. 가입과 로그인 (S-01)
2. 역할에서 보호자 선택 (S-02)
3. 돌봄 대상 추가에서 부모님을 고르고 초대 코드 발급 (S-04)
4. 부모님이 코드를 입력하고 동의 (S-12)
5. 연결 완료 후 카메라 등록 (S-05)
6. 홈에서 카메라 상태 확인 (S-03)

**흐름 B. 부모님(카메라) 측**

1. 가입과 로그인 (S-01), 역할에서 부모님 선택 (S-02)
2. 보호자에게 받은 코드를 입력하고 내용을 읽은 뒤 동의 (S-12)
3. 카메라 송출 화면에서 시작 버튼을 눌러 웹캠을 켬 (S-06)
4. 연결됨 상태가 보이면 화면을 그대로 둠

**흐름 C. 낙상 알림 대응**

1. 인앱 알림 확인 (제목: 낙상 의심, 돌봄 대상 이름, 카메라명, 시각. 푸시는 후속)
2. 알림을 눌러 이벤트 상세로 이동 (S-09)
3. 이벤트 정보 확인 (클립 확인은 클립 저장 구현 후)
4. 판단에 따라 선택
   - 실제 상황이면 확인 완료로 변경하고 부모님께 직접 연락
   - 잘못된 알림이면 오탐 신고
5. 타임라인 (S-08)에서 변경된 상태 확인

**흐름 D. 영상 업로드 분석 (데모와 평가용, 미구현)**

1. 업로드 화면에서 mp4 선택 (S-07)
2. 진행률 확인
3. 결과에서 낙상 구간이 이벤트로 기록되는지 확인
4. 이벤트 상세 (S-09)로 이동해 클립 확인

**흐름 E. 아이 돌봄 대상 추가 (보호자)**

1. 홈 또는 카메라 관리에서 돌봄 대상 추가 선택 (S-04)
2. 유형에서 아이를 고르고 이름 입력, 법정대리인 동의 체크 (S-04)
3. 아이 카메라 등록 (S-05)
4. 아이 방에 둘 기기에서 보호자 계정으로 로그인해 카메라 송출 시작 (S-06)
5. 홈에서 아이 카메라 상태와 베타 안내 확인 (S-03)

**흐름 F. 구역 알림 설정 (아이 카메라, 구역 저장 API만 구현, 판정 미구현)**

1. 카메라 관리에서 아이 카메라의 구역 설정 선택 (S-05)
2. 카메라 화면 위에서 사각형을 그리고 이름과 용도(위험 구역 또는 취침 구역) 선택 (S-13)
3. 취침 구역이면 시간대와 기준 시간 입력 (S-13)
4. 저장 후 홈에서 구역 표시 확인 (S-03)
5. 구역 알림을 받으면 이벤트 상세에서 클립과 구역 이름 확인 (S-09)

**흐름 G. 가족 소통 (두 계정)**

1. 보호자 A가 피드에 사진과 글을 올리고 보여 줄 가족을 고름 (S-14)
2. 연결된 부모님·아이 B 화면에 새로고침 없이 5초 이내 글이 나타남
3. B가 채팅에서 그 글에 답장하고 (S-15), A 화면에 5초 이내 나타남
4. B가 필요한 일을 부탁해에 올리면 (S-16) A가 처리 상태를 바꿈
5. 위치는 각자 원할 때만 공유를 켬 (S-18)

### 4.4 UI 가이드라인 (Tailwind CSS)

보호자 화면은 정보 확인 중심의 모바일 우선 레이아웃이고, 부모님 화면은 글자와 버튼을 크게 키운 단순한 화면입니다.

**컬러 시스템**

| 용도 | 색상 | Tailwind | 비고 |
| --- | --- | --- | --- |
| 주 색상 (버튼, 링크) | 진한 청록 | `bg-teal-700`, 호버 `bg-teal-800` | 흰 글자와의 대비를 확보하려고 700 단계 사용 |
| 위험 (낙상 의심) | 빨강 | `bg-red-50`, `border-red-200`, `text-red-800` | 알림 배너와 이벤트 배지 |
| 주의 (오프라인, 일시정지) | 주황 | `bg-amber-100`, `text-amber-900` | 주황 배경에는 어두운 글자 사용 |
| 정상 (연결됨) | 초록 | `bg-emerald-50`, `text-emerald-800` | 상태 배지 |
| 배경과 카드 | 연회색과 흰색 | `bg-slate-50`, 카드 `bg-white border-slate-200` |  |
| 본문과 보조 글자 | 진회색 | `text-slate-900`, `text-slate-600` |  |

**타이포그래피와 크기**

- 글꼴은 Pretendard(없으면 시스템 sans-serif)를 사용합니다.
- 보호자 화면 본문은 `text-base`(16px), 제목은 `text-2xl font-bold`입니다.
- 부모님 화면(S-06, S-12) 본문은 `text-xl`(20px) 이상이고, 버튼은 `min-h-14 text-xl`입니다 (NFR-09).
- 모든 터치 영역은 `min-h-12 min-w-12`(48px) 이상입니다.

**레이아웃과 반응형**

- 모바일 기준 `mx-auto max-w-md px-4`, 하단 탭은 `fixed inset-x-0 bottom-0 h-16 border-t bg-white`이고 본문에 `pb-20`을 둡니다.
- `md` 이상에서는 하단 탭 대신 왼쪽 사이드바로 바꾸고 `md:grid md:grid-cols-[240px_1fr] md:max-w-5xl`로 배치합니다.
- 성능 리포트(S-11)는 `grid gap-4 sm:grid-cols-2`로 카드를 배치합니다.

**자주 쓰는 컴포넌트 클래스**

| 컴포넌트 | 클래스 예시 |
| --- | --- |
| 기본 버튼 | `min-h-12 rounded-xl bg-teal-700 px-5 font-semibold text-white hover:bg-teal-800 focus-visible:ring-4 focus-visible:ring-teal-300` |
| 위험 버튼 (오탐 신고가 아닌 긴급 동작용) | `min-h-12 rounded-xl bg-red-700 px-5 font-semibold text-white hover:bg-red-800` |
| 카드 | `rounded-2xl border border-slate-200 bg-white p-4 shadow-sm` |
| 낙상 알림 배너 | `rounded-2xl border border-red-200 bg-red-50 p-4 text-red-800` |
| 상태 배지 | `inline-flex items-center gap-1 rounded-full px-3 py-1 text-sm font-semibold` (색은 상태별로 지정) |
| 돌봄 대상 유형 배지 | 공통 rounded-full px-3 py-1 text-sm font-semibold, 부모님 bg-sky-100 text-sky-900, 아이 bg-violet-100 text-violet-900, 아이 베타 표시 bg-amber-100 text-amber-900 |
| 구역 오버레이 | 위험 구역 border-red-500 bg-red-500/20, 취침 구역 border-violet-500 bg-violet-500/20, 구역 이름 라벨 text-xs font-semibold (색과 함께 문구로도 구분) |

**접근성과 사용성 원칙**

- 상태는 색만으로 구분하지 않고 아이콘과 문구를 함께 표시합니다.
- 새 알림과 연결 상태 변화는 `aria-live="polite"` 영역으로 알립니다.
- 확인 완료와 오탐 신고는 되돌릴 수 없으므로 한 번 더 확인하는 대화상자를 둡니다.
- 부모님 화면에는 감시가 아니라 보호자와 연결되어 있다는 문구를 쓰고, 카메라가 켜져 있음을 항상 눈에 띄게 표시합니다.
