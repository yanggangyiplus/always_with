# 아키텍처

브라우저, FastAPI 서버, SQLite 세 층이에요. 소통 기능은 일반 API로 오가고, 위험 알림(낙상 판정)은 서버 안에서 프레임마다 일어나요.

## 소통 기능

| 기능 | 테이블 | 방식 |
| --- | --- | --- |
| 피드 | `posts`, `post_photos`, `post_likes`, `post_audiences` | 사진 5장, 좋아요, 공개 범위, 3초마다 새로 불러오기 |
| 채팅 | `messages`, `message_refs` | 보호자 한 명당 방 하나, 3초마다 새로 불러오기 |
| 부탁해 | `needs` | `requested`, `ordered`, `delivered` 상태 |
| 일정 | `plans` | 같이 보는 캘린더 |
| 위치 | `location_shares` | 본인이 켠 동안만 마지막 위치 한 점 |

## 위험 알림 처리 흐름

```text
브라우저 웹캠 ──(JPEG 프레임, 반복 전송)──> POST /api/cameras/{id}/analyze
                                              │
                                   pose.py: YOLO 포즈 추론 (가장 큰 사람 1명)
                                              │
                                   fall_rule.py: 몸통 각도, 유지 시간, 직전 서 있음
                                              │ 낙상이면
                                   events.py: 이벤트 생성 ──> DB ──> 타임라인, 알림
                                              │
브라우저 <──(관절이 그려진 JPEG)──────────────┘
```

1. 브라우저가 좌우반전한 프레임을 JPEG로 서버에 보내요. 글자가 뒤집히지 않게 반전한 프레임을 보내요.
2. `pose.py`가 YOLO(`yolo26n-pose`)로 관절 17개를 찾고, 사람이 여럿이면 상자가 가장 큰 사람을 골라요.
3. `fall_rule.py`가 어깨와 엉덩이의 중심으로 몸통의 수직 대비 기울기를 계산해요.
4. 낙상이면 `create_event`가 이벤트를 만들고, 보호자는 타임라인과 알림에서 봐요.
5. 서버는 관절이 그려진 프레임을 돌려보내 평소에는 원본 대신 관절 선만 보여 줘요.

## 낙상 규칙 (`fall_rule.py`)

| 상수 | 값 | 의미 |
| --- | --- | --- |
| `LYING_DEG` | 60 | 몸통이 이 각도 이상이면 누운 것으로 봐요 |
| `UPRIGHT_DEG` | 30 | 이 각도 미만이면 서 있는 것으로 봐요 |
| `LYING_SEC` | 1.0 | 누운 상태가 이 시간 이상 이어져야 해요 |
| `UPRIGHT_WINDOW` | 5.0 | 눕기 직전 이 시간 안에 서 있었어야 해요 |
| `MIN_CONF` | 0.5 | 어깨와 엉덩이 중 하나라도 신뢰도가 낮으면 판정하지 않아요 |

낙상 한 번에 경보 한 번만 나가고, 다시 일어서야 다음 경보가 가능해요.

## 설계 결정

| 결정 | 이유 | 대가 |
| --- | --- | --- |
| 규칙 기반 판정 | 근거를 설명할 수 있고 학습 데이터가 필요 없어요 | 천천히 눕는 동작과 구분하지 못해요 |
| 메인 서버에서 추론 | 프로세스 하나로 실행해요 | 추론이 요청을 막아 `_lock`으로 한 번에 하나만 처리해요 |
| 첫 요청에서 모델 로드 | 서버 시작과 테스트가 빨라요 | 첫 프레임이 느려요 |
| 카메라별 판정 상태를 메모리에 보관 | 구현이 단순해요 | 서버를 여러 대 띄우면 상태가 갈라져요 |
| SQLite와 `create_all` | 설치 없이 실행해요 | 마이그레이션이 없어 기존 테이블은 바꾸지 못해요 |
| 사진을 DB BLOB으로 저장 | 파일 저장소가 필요 없어요 | 글당 5장, 장당 2MB로 제한하고 배포 때 다시 봐야 해요 |
| 채팅은 3초마다 새로 불러오기 | WebSocket 없이 구현해요 | 지연과 불필요한 요청이 있어요 |
| 소셜 로그인은 OAuth 인가 코드 방식 | 표준 방식이에요 | 키가 있어야 실제 확인이 돼요 |

## 권한 모델

- 가족은 보호자 1명과 그 보호자의 모든 돌봄 대상 계정이에요.
- 역할은 `guardian`과 `parent` 둘이고, 아이도 `parent`로 표현해요(화면 이름은 "부모님·아이").
- 연결된 보호자만 카메라와 이벤트를 볼 수 있어요(403으로 막아요).
- 피드 공개 범위가 비어 있으면 전체 공개예요. 제한한 글은 대상자와 작성자만 봐요. 보호자도 자동으로 보지는 못해요.
- 소셜 로그인은 서명된 상태 값(JWT)과 쿠키로 CSRF를 막고, 제공자가 확인한 이메일일 때만 기존 계정과 연결해요.
