# 안정성

이상 입력, 권한, 동의, 실패 상황 중 아래를 서버나 화면에서 막고, 가능한 것은 테스트로 확인해요.

## 막는 항목

| 분류 | 상황 | 동작 | 근거 |
| --- | --- | --- | --- |
| 이상 입력 | 중복 이메일 가입 | 409 "이미 가입된 이메일입니다" | `auth.py`, `test_auth` |
| 이상 입력 | 잘못된 형식(이메일, 필수값 누락) | 422, 화면에 "입력한 내용을 확인해 주세요" | `api.ts`, pydantic 검증 |
| 이상 입력 | 읽을 수 없는 이미지 | 400 | `pose.py`, `cameras.py`, `test_analyze` |
| 인증 | 잘못된 비밀번호 | 401, 이유를 구분하지 않는 문구 | `auth.py` |
| 인증 | 토큰 없음 | 401 "인증이 필요합니다" | `deps.py` |
| 권한 | 남의 카메라, 이벤트, 돌봄 대상 | 403 | `deps.py`, `test_child_consent_and_permissions` |
| 권한 | 보호자 전용 기능을 부모님 계정이 사용 | 403 | `deps.py` |
| 동의 | 부모님이 동의하기 전 카메라 등록 | 400 | `cameras.py`, `test_invite_flow` |
| 동의 | 보호자 동의 없이 아이 계정 연결 | 400 | `invites.py`, `test_child_consent_and_permissions` |
| 남용 | 초대 코드를 계속 틀림 | 429, 10분 잠금 | `invites.py`, `test_invite_expiry_and_lock` |
| 만료 | 만료되었거나 이미 쓴 초대 코드 | 400 | `test_invite_expiry_and_lock` |
| 규칙 | 아이 전용 구역을 부모님 카메라에 지정 | 400 | `zones.py`, `test_zone_rejected_for_senior` |
| 규칙 | 카메라당 구역 3개 초과, 오프라인 카메라의 구역 | 400 | `zones.py`, `test_zones` |
| 프라이버시 | 못 보는 피드 글을 채팅에서 인용 | 내용을 가려요 | `family.py`, `test_chat_reply_to_post` |
| 프라이버시 | 위치 공유를 끔 | 저장된 위치를 지워요 | `test_chat_location_and_child_account` |
| 비밀 값 | 비밀번호 저장 | bcrypt 해시 | `core/security.py` |
| 인증 | 소셜 로그인 CSRF | 서명된 상태 값과 쿠키 | `oauth.py`, `test_social_login` |
| 화면 | 카메라 권한 거부 | 허용 방법 안내 | `Stream.tsx` |
| 화면 | 위치 권한 거부 | 안내 문구 | `location.tsx`, `Feed.tsx` |
| 화면 | 목록이 빔, 데이터를 기다림 | 빈 화면 안내, "불러오는 중…" | `Empty`, `Home.tsx` 등 |
| 판정 | 관절 신뢰도가 낮음 | 판정을 하지 않아요 | `fall_rule.py`, 평가 N09 |
| 판정 | 같은 낙상을 반복 보고 | 일어설 때까지 한 번만 | `fall_rule.py` |

## 시연할 방어 장면

1. 잘못된 초대 코드를 연속으로 넣어 잠기는 모습(429).
2. 브라우저 카메라 권한을 거부하고 안내 문구가 뜨는 모습.
3. 동의 전에 카메라를 등록하려고 해서 막히는 모습.

## 아직 못 막는 것

- 서버가 꺼졌을 때 자동 재시도는 없어요. 오류 문구만 보여요.
- 응답이 아주 길거나 이상한 경우, 사진 용량 초과의 화면 안내는 확인하지 못했어요.
- `JWT_SECRET` 기본값 `change-me`는 배포 때 반드시 바꿔야 해요.
- 낙상 추론 지연이 길어질 때의 제한(큐 제한)은 없어요.
- 요청 횟수 제한은 초대 코드에만 있어요.
